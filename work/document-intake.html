The problem

Collecting borrower documents meant chasing files and filing them by hand, and the borrower never knew whether an upload had worked.

What I built

  • A 29-node intake pipeline across Google Drive, GoHighLevel, Twilio SMS, SMTP and Google Chat
  • A custom upload page with a synchronous webhook response contract, so the borrower sees a real success or failure
  • Hardened borrower apps: a URL that worked as a password (?contact_id=) was replaced with signed links plus a one-time code, and scripts and fonts were self-hosted behind SRI and security headers

Key decisions

  • Answer the borrower honestly. The upload page waits for the pipeline's response instead of always saying "done".
  • No guessable links. Signed, expiring links and a one-time code replaced IDs in the URL.

Results

  • 29nodes in one run
  • 5systems updated per upload
  • 0guessable borrower links
