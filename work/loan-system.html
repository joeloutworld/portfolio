The problem

Loans were tracked in two spreadsheets, with no single place for conditions, documents, fees and servicing. The data is borrowers' financial records, so a leak is not an option.

What I built

  • Loan file, pricing engine, conditions and document management
  • A borrower portal, contacts, fees and revenue splits, and reporting
  • Servicing: payoffs, late fees, extensions and construction draws
  • A rules engine (triggers, conditions, actions, a daily digest) that runs every 15 minutes
  • Two-way GoHighLevel sync for contacts, opportunities, notes and conversations

Key decisions

  • Two security layers. A deny-by-default can(actor, action, resource) check on every read and write, backed by FORCE ROW LEVEL SECURITY on every table, so a route that forgets a check returns nothing.
  • Sign-in. Scrypt passwords to NIST 800-63B, a mandatory emailed one-time code, lockouts counted in SQL so racing requests cannot slip past, and sessions revoked on offboarding.
  • Documents. Uploads land in a quarantine bucket, are checked by magic bytes and structure (PDFs with JavaScript and macro Office files are rejected), and are served by short-lived signed URLs with an append-only access log.
  • No double emails. A unique index on (rule, dedupe key) means a retried or overlapping run cannot send the same email twice.
  • Deploys. Multi-stage Docker images with no source or secrets, Traefik with TLS and HSTS, a Neon branch per environment, and a tagged image before every deploy for one-command rollback.

Results

  • 850+automated tests
  • 56reviewed migrations
  • 30database check scripts
  • ~59klines of TypeScript

A full-codebase audit (155 files read) found money-calculation defects that tests and types had not caught, and they were fixed.
